## Backend compatibility and boundaries

Migration: `supabase/migrations/20261116214132_r10_class_ids_and_final_answer_resume.sql`, generated
with Supabase CLI `migration new`, then exercised only by the isolated R9 database runner.

It adds the class-ID results API and timing metadata API, and updates the private question-open
function's saved-question guard. No table, pupil data, RLS policy, key, password or timer duration
changes. New definer timing code fixes an empty `search_path`, uses the existing homework/code
validation and rate budget, and returns timing metadata only for that pupil's current quiz. Its
wrapper preserves controlled malformed-code validation. Class results remain SECURITY INVOKER. All
grants are explicit and covered by the execution allow-list tests. The existing public APIs are
retained.

The timing RPC reveals no answers or question text. Both new RPCs must exist before these frontend
files are published. **Do not merge this branch into live `main` first:** Pages would publish the
frontend automatically, while the hosted database would still lack the new RPCs.
