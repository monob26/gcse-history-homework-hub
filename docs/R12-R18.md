  `quiz_session`. Removing the older API requires a coordinated retirement of that fallback.
- The hosted R12 objects already exist. Use the migration for rebuilding fresh databases. Apply only
  the four reviewed function replacements from R17 to LIVE after separate authorisation.
- The TEST HTTPS response carried a Cloudflare Ray ID. Cloudflare documents that its edge sends
  `CF-Connecting-IP` to the origin. The project-level origin and alternate gateway trust settings
  were not independently audited. Confirm that boundary with Supabase before relying on it for real
  pupil use. The address-bucket behavior itself passed the database tests.
  [Cloudflare HTTP headers](https://developers.cloudflare.com/fundamentals/reference/http-headers/#cf-connecting-ip)
- Run the hub and mirror checks in PR CI. The mirror workflow pins the canonical workflow and the
  hub commit to test. Update both references together for each mirror release. Use the check names
  shown in the PRs when configuring branch protection. Preserve existing restrictions, require pull
  requests and both checks, and apply the requirements to administrators. The hub configuration
  candidate is [recorded here](r8/main-protection.proposed.json).

  token returned HTTP 400 `captcha_failed`. The [R11 release record](R11-live-release.md) documents
  the owner’s confirmation that the secret was regenerated. Provider-side rotation and a solved LIVE
  challenge remain independently unverified. The two-email hourly cap remains the accepted limit. No
  custom SMTP host is configured. Agree a provider before departmental reliance on password
  recovery.
