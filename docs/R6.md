# R6 consolidation

The existing hub repository is the source for both static pages and the backend.

- `pupil/` and `teacher/`: HTML, CSS and JavaScript for each page.
- `shared/`: browser-visible Supabase configuration and page-scoped colour palettes.
- `supabase/`: existing version-controlled backend files copied unchanged from
  `review/r4-pupil-timers` at `88b84c8`.
- `index.html`: generated pupil entry for the existing root Pages URL.

Both pages remain plain static files. Node dependencies are development tools only; there is no
application build. Keep the existing palettes and fonts: consolidating their definitions does not
change the appearance of either page.

## Existing URLs

- Pupil: <https://monob26.github.io/gcse-history-homework-hub/>
- Teacher: <https://monob26.github.io/history-teacher-dashboard/>

The hub continues publishing from `main:/`. Its root entry uses `pupil/` assets and `shared/`
configuration. The teacher repository is a deployment mirror: its root entry uses `teacher/` assets
and its own copied `shared/` directory. This avoids cross-site asset dependencies and keeps the
teacher Auth redirect unchanged.

## Preparing deployment files

From the hub repository:

```sh
python scripts/prepare-pages.py pupil work/pupil-pages
python scripts/prepare-pages.py teacher work/teacher-pages
```

Copy `work/pupil-pages/index.html` to the hub root after editing the pupil HTML. The `pupil/` and
`shared/` source files already live beside that root entry. For the teacher mirror, copy the
prepared `index.html`, `teacher/` and `shared/` into a branch of the teacher repository and open a
release PR. Make source edits in this hub repository, then regenerate the mirror; do not edit the
mirror directly. The copy script does not delete destination files or deploy anything.

Publish the canonical hub PR first and verify its static assets, then publish the prepared teacher
mirror PR. Each site has a self-contained asset tree, so either site can be rolled back
independently. Do not remove the shared files while either page entry references them. Rolling back
a release PR restores the preceding HTML.

## Local checks

```sh
npm ci
npm run format:check
npm run test:r6
python -m http.server 8000
```

Open `/`, `/pupil/` or `/teacher/` on the local server. The browser tests intercept backend requests
with fictional responses and block other external requests. They do not recreate hosted fixtures or
run database migrations.

## Backend preservation

The existing SQL files are imported byte-for-byte and excluded from formatting. They are historical
migration artifacts, not new changes to apply. Local R2 and R3 filenames differ from the versions
assigned during hosted deployment; the baseline also predates hosted migration history. Do not run
blanket `supabase db push` or repair migration history as part of R6. Environment-specific fixtures
remain outside `supabase/migrations/`; never replay them. No credentials, hosted pupil codes or
attempt tokens are exported by this consolidation.

The historical schema snapshot is retained as recorded on the review branch. It does not replace the
subsequent migrations or claim a new hosted export. The later hosted resume-acceptance fixture is
not recreated here.

Formatting is a separate commit after the structural refactor, using pinned Prettier. The frontend
files must have no lines longer than 120 characters. Historical SQL is preserved verbatim so its
checksums and deployment evidence remain valid.
