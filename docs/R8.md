## Runner corrections and reproduction

Only the new acceptance runner needed corrections:

- Chromium needed the managed HTTPS proxy and the public-key pins from the environment's supplied CA
  bundle. No blanket TLS-validation disablement was used. The exact backend/CDN origin allow-list
  remained enforced.
- Clearing the password through a hidden form input caused a runner timeout; clearing the DOM value
  directly fixed that cleanup step.
- The initial private-schema probe used the API root, which requires a secret key. A normal bounded
  table GET instead verified schema rejection using the public key, without obtaining a privileged
  key.

To reproduce a fresh run, explicitly target the test project and apply the reviewed fixture DML once
to add a new fictional pupil. Then:

```sh
npm ci --cache work/npm-cache
python3 scripts/prepare-pages.py pupil work/r8-pupil \
  --environment test --test-config docs/r8/test-config.json
python3 scripts/prepare-pages.py teacher work/r8-teacher \
  --environment test --test-config docs/r8/test-config.json
node tests/r8/browser.cjs
```

Supply `R8_TEST_A_PASSWORD` privately through the runtime environment. The runner needs
`/usr/bin/chromium`; it uses `HTTPS_PROXY` and `NODE_EXTRA_CA_CERTS` when provided. Do not run it
against live or replay the initial provisioning fixtures. The runner reports sanitized pass/fail
names, suppressing raw assertion/Playwright errors that might include DOM values. Formatting checks
passed for maintained source and root documentation. No application changes required R6 regressions.
